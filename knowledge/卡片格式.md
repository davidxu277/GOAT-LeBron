# 药方卡格式 —— 给成员2

## 一张卡是什么

**是一段文字说明，不是代码。**

卡片描述"这一招治什么病、为什么管用、大概怎么实现"。
真正的代码由 Agent 的"工兵"角色自己写 —— 这是比赛的核心要求：

> 「为每个阶段编写代码本身就是 Agent 任务的一部分，而不是预先提供好的」

**所以：写 20 张卡，但只提前实现 2~3 个代码模块当范文。**
全部实现完，我们的 Agent 就退化成一个下拉菜单选择器，创新分会很难看。

范文那 3 个要覆盖三种不同类型，因为工兵之后要写的零件五花八门：

| 挑哪个 | 当哪一类的范文 |
|---|---|
| ESMM | 改模型 + 改损失函数。同时它是本数据集最确定提分的一招，不能赌 AI 写得出来 |
| 一个特征零件（如类目兜底） | 加特征 |
| 一个训练零件（如早停策略） | 改训练过程 |

---

## 必须有的六栏

| 栏目 | 干什么用 | 能省吗 |
|---|---|---|
| `治哪些毛病` | 对暗号用。**只能填 symptoms.yaml 里的 id**，可多个 | 不能 |
| `为什么管用` | 军师讲道理的原料。**最重要的一栏** | 不能 |
| `预计能提多少` | 事后与实际结果对账，检验猜得准不准 | 不能 |
| `要花多少力气` | 代码难度 × 训练时间倍数。调度器算性价比要用 | 不能 |
| `前提条件` | 不满足就不提这个方案 | 可留空 |
| `靠不靠谱` | 0~1 的初始分，拍脑袋给。之后被复盘官自动调整 | 不能 |

## 为什么"为什么管用"最重要

比赛有 **20% 的分**，评委看的是"这个 Agent 为什么决定试这一招"。
军师那段讲道理的话，原料全部来自这一栏。

**反面例子**（等于没写）：

> 为什么管用：这是业界常用的方法，效果不错

**正面例子**：

> 为什么管用：冷门商品出现次数太少，它自己那份 embedding 学不出信息。
> 但同一类目下的商品行为相似，所以让冷门商品借用类目的 embedding 顶一顶，
> 相当于借用同类兄弟的经验。出现次数越少，借得越多。

区别在于：正面例子说清了**病根是什么**，以及**这招怎么作用在病根上**。

## 样例卡一

```yaml
编号: 类目兜底
名字: 用类目信息给冷门商品兜底

治哪些毛病: [冷门商品学不动, 新用户不会做]
属于哪个环节: 特征

为什么管用: |
  冷门商品在训练数据里出现次数太少，它自己那份 embedding 根本学不出信息。
  但同一个类目下的商品，用户行为是相似的。
  所以当一个商品出现次数很少时，让它借用所属类目的 embedding 来顶一顶，
  相当于借用同类兄弟的经验。出现次数越少，借得越多。

预计能提多少: {购买AUC: +0.003, 点击AUC: 0}
要花多少力气: {代码难度: 简单, 训练时间倍数: 1.0}
前提条件: [数据里有类目字段 206]
靠不靠谱: 0.6

怎么实现: |
  在 embedding 层后面加一步混合：
    借用比例 = 1 − min(1, 该商品训练集出现次数 / K)
    最终 embedding = (1−借用比例) × 商品自己的 + 借用比例 × 类目的
  K 建议从 20 开始试。
  注意：出现次数只能用训练集统计，不能碰验证集（见 CLAUDE.md R2）。

出处: 冷启动场景下的表示共享，推荐系统常见做法
```

## 样例卡二（本数据集最重要的一张）

```yaml
编号: ESMM
名字: 全曝光空间建模转化率

治哪些毛病: [转化样本偏差]
属于哪个环节: 模型 + 损失函数

为什么管用: |
  买东西的人一定先点过。所以"点了会不会买"只能在点过的人身上观察到，
  可训练出的模型却要对所有曝光做预测 —— 学习样本与使用场景不一致，必然学偏。
  而且转化样本极少，数据太稀。

  这招不直接学"点了会不会买"，改为学"会不会点"和"看了之后会不会买"两件事，
  两者相除得到答案。这样全部曝光都参与训练，学偏和数据稀疏一起解决。

预计能提多少: {购买AUC: +0.01, 点击AUC: 0}
要花多少力气: {代码难度: 中等, 训练时间倍数: 1.2}
前提条件: []
靠不靠谱: 0.85

怎么实现: |
  两个塔共享同一份 embedding 表：
    塔A 输出 P(点击)，塔B 输出 P(购买 | 曝光)
    损失 = BCE(塔A, click) + BCE(塔A × 塔B, click × conversion)
  注意：最终报分时购买 AUC 仍然只在 click=1 的样本上算（见 CLAUDE.md 第五节）。

出处: 阿里 2018 年提出，正是在本数据集上首次发表
```

## 20 张卡怎么分配

按病症覆盖来分，**不要按算法家族分**，保证每个核心病至少有 2 张卡对症：

| 病 | 候选卡 |
|---|---|
| 转化样本偏差 | ESMM、CTCVR 联合建模 |
| 两个任务打架 | MMoE、PLE、损失权重自动平衡 |
| 特征没组合起来 | 启用现成的 4 个交叉特征、DCNv2、DeepFM、FiBiNET |
| 冷门商品学不动 / 新用户不会做 | 类目兜底、频次自适应 embedding 维度、长尾上采样 |
| 历史行为没用上 | 多值字段集合编码、行为序列池化、target attention |
| 在背题 | dropout、权重衰减、embedding 正则、早停 |
| 把握不准 | 概率校准、负采样后的概率还原 |
| 训练太慢 | 负采样降采样、混合精度 |
| 结果不稳 | 多种子平均、checkpoint 融合 |

**优先写「转化样本偏差」和「冷门商品学不动」这两组** —— 它们在本数据集上最确定能拿到分。
