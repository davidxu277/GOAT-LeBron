# 药方卡格式 —— 给写卡的人

## 一张卡是什么

**是一段文字说明，不是代码。**

卡片描述"这一招治什么病、为什么管用、大概怎么实现"。
真正的代码由 Agent 的"工兵"角色自己写 —— 这是比赛的核心要求：

> 「为每个阶段编写代码本身就是 Agent 任务的一部分，而不是预先提供好的」

所以卡片多、现成零件少。全部实现完，Agent 就退化成一个下拉菜单选择器。

现成零件只当**范文**，每一类一个，工兵写新零件时照着它的样子写：

| 范文 | 当哪一类的范文 |
|---|---|
| `modules/models/mlp.py` | 改模型 |
| `modules/features/frequency_bucket.py` | 加特征 |
| `modules/train/early_stopping.py` | 改训练过程 |

## 栏目

| 栏目 | 干什么用 | 能省吗 |
|---|---|---|
| `治哪些毛病` | 对暗号用。**只能填 symptoms.yaml 里的 id**，可多个 | 不能 |
| `为什么管用` | 军师讲道理的原料。**最重要的一栏** | 不能 |
| `预计能提多少` | 事后与实际结果对账，检验猜得准不准 | 不能 |
| `要花多少力气` | 代码难度 × 训练时间倍数。调度器算性价比要用 | 不能 |
| `前提条件` | 不满足就不提这个方案 | 可留空 |
| `靠不靠谱` | 0~1 的初始分，拍脑袋给。之后被复盘官自动调整 | 不能 |
| `怎么实现` | 给工兵的实现草图（不是代码） | 可留空 |
| `失败信号` | 这招失败时长什么样。只喂复盘官，不喂军师 | 可留空 |

## 四条硬规矩（代码或测试会拦）

1. **`治哪些毛病` 只能填词表里的病名**，`预计能提多少` 只能写**当前任务成绩单里的指标名**。
   两条都在 `CardLibrary.load` 里强制校验，写错启动就报错 —— 换任务时不用靠人记得挨个改。
2. **点名的文件必须真的在仓库里**，点名的字段必须真的在本数据集里。
   军师会照着卡片原文去讲道理：卡片引用一个别的仓库的文件，军师就会拿它当证据。
   （`tests/test_knowledge_speaks_current_task.py` 盯着。）
3. **复用现成零件时，给一段 ` ```yaml ` 配置样例**。工兵照抄样例是常态，
   测试会真的拿样例去加载那个零件 —— 键名跟零件读的对不上，测试当场失败。
4. **流水线缺挂载点时，在 `前提条件` 里直说**："目前没有 / 目前不能 + 缺什么"。
   不写的话军师会选它、工兵会白跑一轮，还会被记成"这招没用"。

## 为什么"为什么管用"最重要

比赛有 **20% 的分**，评委看的是"这个 Agent 为什么决定试这一招"。
军师那段讲道理的话，原料全部来自这一栏。

**反面例子**（等于没写）：

> 为什么管用：这是业界常用的方法，效果不错

**正面例子**：

> 为什么管用：冷门视频出现次数太少，它自己那份 embedding 学不出信息。
> 但同一个作者的视频受众相近，所以让冷门视频借用作者的统计量顶一顶，
> 相当于借用同一作者其它视频的经验。出现次数越少，借得越多。

区别在于：正面例子说清了**病根是什么**，以及**这招怎么作用在病根上**。

## 样例卡一：复用现成零件

```yaml
编号: 类目兜底
名字: 用作者信息给冷门视频兜底

治哪些毛病: [冷门视频排不上去]
属于哪个环节: 特征

为什么管用: |
  冷门视频在训练数据里出现次数太少，它自己那份 embedding 根本学不出信息。
  但同一个作者的视频，受众和风格是相近的 —— 让冷门视频借用作者那一层的统计量顶一顶。

预计能提多少: {GAUC: 0.001, nDCG@5: 0.001}
要花多少力气: {代码难度: 改配置, 训练时间倍数: 1.0}
前提条件: []
靠不靠谱: 0.6

怎么实现: |
  零件是现成的，只发 config_patch（这段样例会被测试真的拿去加载）：
    features:
      类目兜底:
        enabled: true
        impl: modules/features/category_fallback.py
        item_field: video_id
        category_field: author_id
        output_field: 作者兜底热度
        K: 20

出处: 冷启动场景下的表示共享，推荐系统常见做法
```

## 样例卡二：要工兵写新零件（本数据集最值钱的方向之一）

```yaml
编号: 用户历史序列
名字: 把用户"之前看完过什么"做成特征

治哪些毛病: [历史行为没用上]
属于哪个环节: 特征

为什么管用: |
  现在进模型的只有当次曝光自己的字段，用户过去看过什么、看完了什么一点都没进来。
  这个用户过去对同一个作者、同一个 tab 的视频看完的比例，
  回答的正是评测在问的问题 —— "在他自己的候选里，哪一条他更可能看完"。

预计能提多少: {GAUC: 0.004, nDCG@5: 0.004}
要花多少力气: {代码难度: 中等, 训练时间倍数: 1.1}
前提条件: []
靠不靠谱: 0.7

怎么实现: |
  新写一个加特征零件。时间纪律：训练集每一行只能用严格早于它那一天的行来算，
  验证集用整个训练集算。标签在流水线里的列名是 label。

出处: 官方 KuaiRand Starter Kit 的 headroom 分析
```

## 卡怎么分配

按病症覆盖来分，**不要按算法家族分**，保证每个核心病至少有 2 张卡对症。

现在每个病有哪几张卡、哪些病还没有药，跑一下就知道（不在这里手抄一份 —— 手抄的会过期）：

```bash
python -m agent.cli check
```
