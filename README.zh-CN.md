# GOAT-LeBron

**TikTok TechJam · 赛道二 —— 面向推荐系统的自主机器学习研究智能体**

> **我们做的不是推荐模型，是造推荐模型的机器人** —— 而且它每做一个实验，
> 都得用文字讲清楚这个实验为什么值得做。

*[English README](README.md)*

---

## 一、这个项目是什么

算法工程师平时干活是这样一个圈：

> 看指标 → 猜哪里有问题 → 写代码 → 训练 → 看分数 → 决定下一步试什么 → 再来一遍，直到分数不再涨

**这个项目把这个圈自动化了，连"猜"那一步也包括在内。** 把数据集和评分规则交给它，
然后人不碰键盘。它自己读成绩单、说出哪里有病、挑一个药方并讲清理由、写代码、训练，
最后判断自己当初的假设到底对没对。

跑完之后交出两样东西：一个训练好的排序模型，和一份完整记录它每一步在想什么的日志。

### 为什么不直接"随便改代码，留下分数高的那版"？

因为有一种失败比"分数没涨"更隐蔽：

> 医生说孩子数学不好 → 你请了数学家教 → 期末总分涨了 3 分 → **可数学一分没动**，
> 涨分来自一张简单的语文卷子。把这记成"家教有用"，你会一直花钱请数学家教，
> 离真正的问题越来越远。

一个分不清这两种情况的智能体，会越跑越自信地攒下一堆错误结论。所以这个智能体
每次实验**之前**必须先写下假设，实验之后由**代码**（而不是提示词）检查：
它当初指着的那个具体数字，到底动了没有。

## 二、整个流程

### 一场是这样跑的

```
  人只给两样东西：数据 + 评分规则
      ↓
  第 0 轮 · 先原样跑一次，拿到第一份成绩单
      ↓
  ┌─→ 一轮 · 诊断 → 开药 → 写代码 → 训练 → 复盘
  │       ↓
  │   产出新成绩单
  │       ↓
  │   还能接着改吗？
  │       │
  └───────┤ 能 —— 新成绩单交给下一轮的医生
          │
          │ 不能 —— 满足任一条就停：
          │           · 连续 N 轮提升都没超过 ε
          │           · token 预算烧完了
          │           · 在全量数据上也查不出病了
          ↓
  挑出验证集分数最高的那一轮 → 它的配方就是我们要交的东西
```

轮和轮之间是连着的：试过失败的卡会被拉黑，已经生效的卡不会再提第二遍，
没被选中的方案放上"待议架"，只要还对症就会再摆到军师面前。

### 一轮里发生什么：四个角色接力

```
  成绩单  →  ① 医生  →  筛卡片   →  ② 军师  →  调度器
              查出病     集合求交     挑 3 个    挑 1 个
              排严重度   （不调模型） 讲清理由   （不调模型）
                                                  ↓
  下一轮  ←  ④ 复盘官 ←   训练   ←  ③ 工兵  ←─────┘
              猜对了吗   出成绩单    写代码
```

| | 角色 | 干什么 |
|---|---|---|
| ① | **医生** | 读成绩单，说出有哪些病，按严重度排序 |
| | *筛卡片* | *纯代码 —— 拿病名跟药方卡库求交集* |
| ② | **军师** | 挑 3 个药方；每个都要写清治哪个病、预计提多少、成本、失败时长什么样 |
| | *调度器* | *纯代码 —— 按性价比挑 1 个，并决定用多大一份数据跑* |
| ③ | **工兵** | 把它变成代码 —— 改配置，或者在 `modules/` 下写一个新零件 |
| | *训练* | *真训练、真评分、出新成绩单* |
| ④ | **复盘官** | 判断假设成没成立，更新这张卡的"靠谱度" |

**斜体的三步不调用任何模型。** 大模型只在四个决策点被叫起来 —— 这是 token
预算能压得很小的原因，而 token 用量是计分的。

## 三、跟别的做法不一样在哪

### 3.1 先诊断，再开药

"改代码碰运气"型的智能体是在盲搜：改点什么，看数字动没动。它们从来不形成
"到底哪里出了问题"的判断。

```
证据   「曝光 <10 次」那一桶 GAUC 0.611，「曝光 >1000 次」那一桶 0.684
       —— 差 0.073，而且这一桶占 22% 的曝光
         ↓
诊断   「冷门视频排不上去」（严重度 0.7，确定度高）
         ↓
开药   从治这个病的卡里挑 → 比如「用作者信息给冷门视频兜底」
       理由：曝光不到 10 次的视频学不出自己的 embedding，
            借用同一作者的统计量，正好作用在这个病根上
```

医生和药方卡之间的暗号，是一张 **12 个病名的词表**（`knowledge/symptoms.yaml`）。
医生的输出结构把病名锁死成 enum —— 它**在物理上就说不出**一个没有卡能治的病。
所以筛卡片就是一次集合求交：不花钱、结果确定、永远不会"幻想"出一个对得上的卡。

### 3.2 它骗不了自己

下面这些是 `agent/roles.py` 里的校验器，不是提示词里的一句话：

```python
# 声称假设成立，却承认目标病一个都没好转
if all_targets_unresolved and verdict == "correct":        reject

# 更隐蔽：声称某个病好了，可它自己报的前后两个数一模一样
if resolved in ("yes", "partly") and before == after:      reject

# 这点变化还没有换随机种子带来的抖动大
if max_change < noise_band and verdict == "correct":       reject

# 方案说要治 3 个病，就得 3 个都交代清楚
if any target symptom is unaccounted for:                  reject
```

打回不是扔掉 —— 违反了哪一条会原文引给这个角色，让它重新回答。

> **提示词是墙上的标语，校验器才是墙。** 我们写成提示词的每一条约束，最后都被
> 违反过；写成校验器的，一条都没被突破。

### 3.3 它知道自己的测量误差有多大

"冷门桶比热门桶低 0.03"算不算一个发现？只有当 0.03 比这个数字自己的抖动还大时才算。

设计上是这样：同一份配置，只换随机种子，跑 N 次 —— 小于这个抖动带的差距，
不许报成病，也不许说成提升。在某一档数据上量出来的带子，绝不会被悄悄拿去卡
另一档的结果；对不上就不用，并写进结果表。

**在这个数据集上的现状：** 门槛这套机制已经就位，但量抖动的工具当初是照上一个
数据集的双塔漏斗写的，随它一起拆掉了。在 KuaiRand 上，所有门槛目前都退回一个
固定的兜底值 0.0005，开跑时系统会当面说清这一点（见第九节局限 2）。

带子还是**分指标**的。两个指标的抖动差一个数量级时，不能共用一个门槛：稳的那个
指标的真实提升会被抖得凶的那条带子淹掉，而抖得凶的那个自己抖一下就越过了共用
门槛，白拿不该拿的信任分。

### 3.4 故意不让智能体看到官方基线

比赛按"相对官方基线的提升"排名。**那是评委的尺子，不是智能体的输入。**

一旦把这个数给它，它会退化成对着一个常数调参：超过了就说"没病"，低于就笼统报
"学得不够"。它不再去读训练/验证差距、分桶、用户构成 —— 那些真正能定位病因的证据。

这个教训是花了代价换来的。病名表里曾经写死过"官方基线 GAUC 0.6016"。那个数其实
是**主分**，不是 GAUC；真正的 GAUC 基线是 0.6674。我们的模型跑出 0.6638 —— 三个指标
全部**低于**基线 —— 医生读着我们写错的常数，得出"明显高于基线"，什么病都没报。
没有任何东西崩溃。一个写错的常数，在完全安静中把结论整个颠倒了。

基线仍然全程记录在 `final_summary.json` 里，给人看。有一条测试保证：这些数字
不会出现在智能体读得到的任何地方。

## 四、怎么活下来

鲁棒性是计分的，所以它是设计出来的，不是祈祷出来的。

| 出了什么事 | 怎么应对 |
|---|---|
| 某个角色抽风（格式不对、网络断了） | 五个环节各有自己的保险丝 —— **最多浪费这一轮，绝不拖垮整场** |
| 工兵写的代码没过校验 | 把错误喂回去重试；再不行就换备选方案 |
| 训练崩了或者超时 | 复盘结论**由代码**合成 —— 不为一次没结果的运行浪费一次大模型调用 |
| 同一个主意反复出现 | 试过的卡拉黑；已经生效的卡不会再提 |
| 连续几轮查不出病 | 升一档数据；已经是全量了就判收敛 |
| 进程跑到一半死了 | 日志和三本账每轮都落盘，重启就能接着跑 |
| 改动悄悄没生效（零件没加载上、配置键没人读） | 验证集预测做指纹；跟上一轮一模一样 → 判"未生效"，这张卡的信任分受保护 —— 该修的是流水线，不是这个主意 |
| 失败的一轮把补丁留在了身后 | 补丁历史回滚，一轮失败污染不了之后每一轮 |
| 一轮接一轮连跑都跑不起来 | 连续 `patience` 轮失败就停，不把整场预算烧光 |

训练在单独的子进程里跑，有硬性的墙钟超时（先 `terminate`，不行再 `kill`），
卡死的训练吃不掉整场预算。每一次磕绊和恢复都写进日志 —— 那就是鲁棒性的证据。

## 五、任务与计分

**数据集** —— KuaiRand-Pure。标签 `long_view`。在已有曝光上做用户内排序，不做全库召回。

| | |
|---|---|
| 指标 | **GAUC** 和 **nDCG@5**；主分 = 两者平均 |
| GAUC 统计范围 | 只统计 `0 < 正例数 < 曝光数` 的用户，按正例数加权 |
| nDCG 统计范围 | 所有用户；零正例用户记 0 |
| 切分 | 训练 2022-04-08→04-21 · 验证 04-22→04-28 · 测试 04-29→05-08 |
| 收敛 | 主分 ε = 0.002，patience = 3 |
| 预算 | ≤ 50 次训练，≤ 6 小时墙钟 |

**官方基线**（starter kit）：一个因子分解机，k=16，lr=0.001，五个类别字段，纯 NumPy。

| | GAUC | nDCG@5 | 主分 |
|---|---|---|---|
| 验证集 | 0.6674 | 0.5357 | 0.6016 |
| 隐藏测试集 | 0.6610 | 0.5282 | 0.5946 |

排名用的是**验证集最佳**那一轮相对这个基线的绝对提升。计分还会看智能体本身 ——
推理的质量、人工干预有多少次、消耗了多少算力和 token。**日志本身就是分数的一部分。**

## 七、安装

需要 Python ≥ 3.9。

```bash
git clone https://github.com/davidxu277/GOAT-LeBron.git
cd GOAT-LeBron

python -m venv .venv
.venv/bin/pip install -r requirements.txt          # Windows：.venv\Scripts\pip
.venv/bin/pip install -e kuairand_goat_bridge      # 这样 `python -m kuairand_bridge` 才能用
```

不做可编辑安装的话，bridge 的命令前面要加 `PYTHONPATH=kuairand_goat_bridge/src`。

下载 **KuaiRand-Pure**，把配置指向放 CSV 的那个目录：

```yaml
# kuairand_goat_bridge/configs/kuairand_task.yaml
data_dir: /absolute/path/to/KuaiRand-Pure/data
```

花钱之前先验一遍数据：

```bash
.venv/bin/python -m kuairand_bridge preflight --data-dir /path/to/KuaiRand-Pure/data
# verified: train 1,141,112 · valid 124,909 · test 170,588
# `official_row_counts_match: true` 表示切分跟 starter kit 完全一致
```

大模型凭据（四个角色要用；下面的离线检查不需要）：

```bash
export AGENT_PROVIDER=deepseek DEEPSEEK_API_KEY=...
# 或者：export ANTHROPIC_API_KEY=sk-ant-...
```

## 八、复现步骤

### 第 0 步 —— 免费检查（不联网、不花钱）

```bash
.venv/bin/python -m agent.cli check                      # 病名词表 ↔ 药方卡是否自洽
.venv/bin/python -m pytest tests/ kuairand_goat_bridge/tests/ -q
.venv/bin/python -m agent.cli run --offline --rounds 8   # 演习一整场
```

演习用假模型和假执行器检查的是**接线**：状态有没有在轮与轮之间传下去、某个角色崩了
能不能恢复、该停的时候停不停。故障可以按需注入：

```bash
.venv/bin/python -m agent.cli run --offline --rounds 8 --fail-round 3 --fail-role-call 2
```

演习日志写在 `logs/offline/`，绝不会混进交付物的日志。

### 第 1 步 —— 复现官方基线（约 30 秒）

```bash
.venv/bin/python -m kuairand_bridge goat-run \
    --config kuairand_goat_bridge/configs/fm_baseline.yaml --dry-run
```

这份配置设了 `require_baseline_reproduction: true`：第 0 轮必须落在官方主分 0.003 以内，
否则整场中止。**先做这一步** —— 它证明流水线复现得出官方的数，之后的提升才能算在
智能体头上，而不是流水线的偏差。

### 第 2 步 —— 噪声带：**这个数据集上暂时没有**

量抖动的多种子工具当初是照上一个数据集的双塔漏斗写的，随它一起拆掉了。
KuaiRand 版（针对用户内 GAUC 和 nDCG@5 的带子）还没写。

这一步什么都不用做 —— 但要清楚它意味着什么：所有"这算不算真提升"的门槛都退回
一个固定的兜底值 **0.0005**，那是拍出来的，不是在这份数据上量的。开跑时系统会
当面说清，不假装量过：

```
⚠️ 没测过噪声带，全程用 R11 的兜底门槛 0.0005
   （一个拍出来的数，不是这份数据上量的）
```

这是局限 2，也是时间再多一点时我们最先要补的。

### 第 3 步 —— 自主跑一整场（人不碰键盘）

```bash
.venv/bin/python -m kuairand_bridge goat-run \
    --config kuairand_goat_bridge/configs/kuairand_task.yaml
```

> ⚠️ `configs/kuairand_task.yaml` 必须指向 `examples/goat_trainer.py`。另一个 trainer
> 按设计只收 6 个超参数、拒收新文件 —— 正式跑指向它，等于悄悄把智能体降级成拧旋钮的。
> `tests/test_configs.py` 盯着这一条。

中途只要插了手，就记一笔 —— 自主性得分要求这个数是真实观察，而不是写死的 0：

```bash
.venv/bin/python -m agent.cli intervene "第 7 轮 OOM，调小了 batch size" --round 7
```

### 第 4 步 —— 收交付物

什么都不用跑：一场跑完，所有东西都在配置的 `output_dir` 下（默认 `output/agent_run/`）。

| 产物 | 交付物 |
|---|---|
| `logs/rounds.jsonl` | **#3** 逐轮日志：假设、完整代码改动、指标、出错与恢复 |
| `logs/narrative.md` | **#3** 给人读的版本：一整场压成一条故事线 |
| `logs/session_summary.json` | **#4** 结果表：最佳分数、相对基线的提升、token、墙钟、GPU 小时、人工干预次数 |
| `logs/snapshots/` | 每一轮的配置和零件代码 —— 任何一轮都能还原 |
| `final/` | 验证集最佳那一轮在全量数据上重放一遍，附带检查过的测试集提交 |
| `final_summary.json` | 最佳分数、基线复现检查、提交文件、整场汇总 |

> **提交的是最佳那一轮，不是最后一轮。** 智能体的改动是**层层叠加**的：跑到第 20 轮，
> 流水线上是整摞改动，第 5 轮的状态早就没了。收敛之后，bridge 会把最佳那一轮的
> 补丁历史原样在全量数据上重放一遍，产出提交文件 —— 一轮都没超过基线时，交的就是
> 第 0 轮，也就是官方基线本身。

### 什么算人工干预

开跑前就定好，不事后调整：

| 不算干预（准备工作） | 算干预（碰了正在跑的那一场） |
|---|---|
| 下载、预处理数据 | 跑到一半改配置或代码 |
| 写药方卡、提示词、病名词表 | 杀掉某一轮、重启进程 |
| 定轮数、预算、起步档位 | 手动挑交哪一版 |
| 装环境；开跑前修自己的 bug | 跑到一半修 bug 再接着跑 |

## 九、局限，以及时间再多一点会怎么改

这些是我们自己知道的问题，在别人指出之前先说出来。

**1. 判病是大模型做的，不是代码做的。** 判定规则以文字形式交给模型，算术也是模型在做。
这不可复现 —— 同一份成绩单跑两次可能得出不同的诊断 —— 算术还可能算错。
*改进：* 用代码确定性地算规则，让医生去掂量确定度、排严重度、注意规则没覆盖到的东西。
诊断应该是确定的；创新在军师的推理里，不在医生的减法里。

**2. 这个数据集上从来没量过噪声带。** 量抖动的工具当初是照上一个数据集的双塔漏斗
写的，随它一起拆了；它的解析兜底假设的是普通 AUC，搬不到用户内 GAUC 上，而 nDCG@5
根本没有闭式标准误。在 KuaiRand 版出来之前，所有门槛都退回固定兜底值 0.0005 ——
那是拍出来的。系统开跑时会当面说出来，不假装量过。
*改进：* 针对用户内排序指标，用多个种子实测抖动带。

**3. 复盘官报的前后两个数仍然是它自己报的。** 代码会检查这些数跟它自己的结论是否
**自洽** —— 说某个病好了、前后两个数却一模一样，会被打回 —— 但没法核实这些数是从
成绩单上抄的，而不是编的。要真正解决，得先解决局限 1。

**4. 训练集分数走的是推理路径。** 判"在背题"要比训练集和验证集的分数，但训练集分数
是用每个零件的 `transform` 算的，而不是训练时用的折外路径。对目标编码这类零件，
这会让训练集分数略微偏高。成绩单上带着明确的口径提醒，医生对刚过线的差距会打折扣。

**5. 一轮只改一处。** 这是故意的：一轮改两处、分数涨了，就没法归因，
整个"病到底好没好"的机制就失效了。组合拳交给**复合卡** —— 一张卡把必须一起上的
改动打包。代价是覆盖得慢一些。

**6. 提示词的质量只在很少的样本上验证过。** 测试把**强制执行**这一层盖得很全
（证据有没有带数字、禁用字段拦不拦得住、复盘官能不能骗自己、状态能不能在轮与轮之间
传下去）。可提示词能不能引出好的推理，只能靠读真跑的日志来判断，而我们读得还不多。

**7. 没做附加的 benchmark。** 只做了必做的 KuaiRand-Pure。在有限时间里硬上
KuaiRand-1k 和 27k，大概率两边都做不好。

## 十二、比赛之后

比赛提交的版本由 tag `submission-techjam2026` 钉住。之后的工作集中在一件事上：
让智能体**没法**再自己把自己搞垮，而不是发现一个洞补一个洞 —— 下面每一项改动都带着
一条"没有它就会失败"的测试。

- **知识库没法再悄悄过期。** 药方卡、提示词、交给工兵的范文和硬规矩，都跟派生出来的
  事实对一遍：当前任务的指标名、仓库里真实存在的文件、数据里真实存在的字段。
  比赛中途换数据集时，14 张卡里有 11 张还在引用上一个任务的指标。
- **一个任务，一条流水线。** 上一个数据集的流水线整个拆掉了；一条守卫测试盯着，
  不让它的字段名和指标名再回到代码里。
- **补上卡片一直在承诺的挂载点。** 模型零件自己写的 `loss` 现在会真的被用上
  （以前被悄悄覆盖掉），所以配对排序、时间衰减这两张卡落得了地。连续特征按训练集
  分位数分档，不再被当成一个个 ID —— 造数据实测，以前验证集有 37% 的行落进"没见过"。
- **修掉几个一声不响就把结果弄错的 bug。** 目标编码在整数 ID 上整列输出一个常数；
  真跑时交给工兵的范文是一个过期的、只能改配置的 trainer；一个遗留的分数改名适配器，
  让结果表把每一场都报成"比官方基线低 0.67"。
