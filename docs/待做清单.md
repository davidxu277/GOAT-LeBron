## B. 证据类 —— 简历和答辩最值钱的部分

### ~~B1. 噪声带实测~~ · 2026-09-26

计划 `docs/superpowers/plans/2026-09-26-noise-bands.md`。
`python -m kuairand_bridge noise --config <任务配置> --fidelity 小份 --seeds 5`，
结果写 `<output_dir>/logs/noise_bands.json`，`goat-run` 自动读。
执行器新增 `sample_seed`：量的时候数据子集钉死、只换训练种子
（以前一个 seed 同时管抽样和初始化，换种子会把抽样抖动也量进去）。

实测（goat_trainer 默认配置，5 个训练种子，验证集全量 12.5 万行）：

| 档位 | GAUC 噪声带 | nDCG@5 噪声带 | 主分噪声带 | 每次耗时 |
|---|---|---|---|---|
| 小份（15%） | 0.0054 | 0.0024 | 0.0037 | ~12 秒 |
| 中份（40%） | 0.0042 | 0.0026 | 0.0031 | ~18 秒 |

噪声带 = 2×√2×标准差：两次同配置跑，差距约 95% 落在带内。

**这组数说明的事（影响后面每一项）：**

1. R11 的兜底 0.0005 比实测窄 5~10 倍。没量带子时，一次 +0.001 的「提升」
   会被判「猜对了」、给卡片 +0.15 信任分 —— 其实是换了个种子的程度。
2. 官方收敛门槛 epsilon = 0.002（主分）比主分的噪声带 0.003 还小：
   单种子比较分辨不出 0.002 的提升。B4 对比实验必须每组多种子跑，否则结论是噪声。
3. 数据从 15% 加到 40%，带子只窄了 20%：抖动主要来自模型初始化，不是数据量。
   「升到大数据就能看清」这个假设在这里不太成立，要看清只能多种子。
4. 卡片「预计能提多少」大多写的是 +0.001~0.004，一半以上低于噪声带。

5 个种子本身也不多（标准差的估计有 ±35% 左右的误差），数量级是可信的，第三位小数别较真。

### ~~B2. 锁定集：整场只评一次的考场~~ · 2026-09-26

计划 `docs/superpowers/plans/2026-09-26-holdout.md`。`kuairand_task.yaml` 默认 `holdout_users: 0.2`：
验证集按用户（crc32 分桶）切两成当锁定集。一场里训练的早停、每轮打分、医生的分组证据
全部只看另外八成（开发集）；整场结束拿第 0 轮和最佳轮在同一档数据上各训一次，
报「开发集涨了多少 / 锁定集涨了多少 / 挑出来的运气」，写 `logs/holdout_report.json`。
最终提交仍在全量验证集上打分，跟官方基线直接可比。大考占 2 个训练名额，开跑前就留出来。
量噪声带也跟着走开发集（小份开发集：GAUC 0.0065 / nDCG@5 0.0028 / 主分 0.0045）。

怎么验的：真数据小份，第 0 轮 + 「视频热度分桶」零件，然后大考。

| | 开发集 GAUC | 锁定集 GAUC |
|---|---|---|
| 第 0 轮 | 0.6399 | 0.6217 |
| 加视频热度分桶 | 0.6386（−0.0013） | 0.6252（+0.0036） |

- 大考重训出来的开发集分数跟跑的时候逐位相同 —— 重放补丁历史是确定性的，比的确实是那两个版本
- 第 0 轮开发集和锁定集就差 0.018：两拨用户难度不一样。所以结果表不再报
  「最佳轮开发集分 − 锁定集分」（会把这 0.018 人群差异误读成「迎合开发集」），改成比涨幅
- 这个改动两边的涨幅都在噪声带以内（锁定集只有两成用户，带子估计是全量的 2 倍左右），
  单次比较什么也说明不了 —— 又一次印证 B1：要下结论就得多种子
