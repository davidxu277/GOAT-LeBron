# 四个角色的输入输出契约

> 负责人：成员3 · v0.1 · 2026-08-26
> 需成员1、2、4 确认（见文末清单）

## 总原则：任何两个 AI 角色之间，永远隔着一段普通代码

每一步的输出先落成结构化文件，中间的筛选、排序、预算判断全部用普通 Python 完成。
好处：可存档、可回放、可单独调试，且大幅省 token（token 总量占评分 15%）。

```
一轮训练结束
  ↓  [成员1 + 成员4 生产，纯代码]
成绩单 health_report
  ↓  ① 医生（大模型）
诊断书 diagnosis
  ↓  [纯代码：按病名过滤卡片 → 命中 3~5 张]
  ↓  ② 军师（大模型）
提案 proposals（3 条）
  ↓  [成员4 调度器：选 1 条 + 定数据尺寸，纯代码]
  ↓  ③ 工兵（小模型）
改动 patch
  ↓  [成员4：红线校验 + 5k 行冒烟测试] → 执行训练
  ↓  ④ 复盘官（大模型）
复盘 reflection → 更新实验库与卡片可信度 → 回到顶部
```

**四个角色一律走结构化输出**（tool use / response_format），不要自由生成后正则解析。
解析失败重试 1 次，再失败记一条恢复事件。

下面四节的示例是**连贯的同一轮**，可当作一个完整案例阅读。

---

## ① 医生

**输入**：成绩单、最近 5 轮的精简记录、`knowledge/symptoms.yaml`

**输出**

```yaml
findings:
  - symptom: 冷门商品学不动     # 只能是 symptoms.yaml 里的 id
    severity: 0.82              # 0~1
    confidence: 高              # 高 / 中 / 低
    evidence: "商品出现次数<10 桶购买AUC=0.611，>1000 桶=0.682，
               差 0.071；该桶占样本 34%"
    affects: [购买AUC]
no_finding: false
reason_if_none: ""
```

**硬规矩**

1. `symptom` 只能从 `symptoms.yaml` 里选，不许自创
2. `evidence` 必须引用成绩单里的具体数字，禁止"明显偏低""表现不佳"
3. 最多 3 条，按 `severity` 降序
4. 必须检查每个分组的样本量，**样本太少的分组不能作为证据**
5. 证据不足就给 `confidence: 低`，或直接 `no_finding: true` —— **不许硬凑病**

> 第 5 条不要省。一个会说"这轮看不出明显问题"的医生，比一个永远能诊断出毛病的
> 医生可信得多，评委翻日志时能看出区别。

## ② 军师

**输入**：医生的前 2~3 条诊断、**已按病名过滤过的** 3~5 张卡、本轮已试过什么、
剩余预算（宽裕/一般/紧张）、当前配置摘要

**输出**（3 条候选，已排序）

```yaml
proposals:
  - rank: 1
    card_id: 类目兜底
    targets: [冷门商品学不动]
    rationale: |
      低频桶购买AUC 0.611，比高频桶 0.682 低 0.071，且占 34% 样本，
      是当前最大失分来源；病根是低频商品出现次数太少，embedding 学不出信息。
      该卡机制是用类目 embedding 为低频商品兜底，正对这个病根。
    expected: {购买AUC: +0.003, 点击AUC: 0.000}
    cost: {代码难度: 简单, 训练时间倍数: 1.0}
    risk: "K 取太大会稀释热门商品自身表示"
    novel: false          # true = 卡片库里没有，自己想的
```

**硬规矩**

1. `rationale` 必须走完两段因果：**证据 → 病根**，**病根 → 这招为什么对症**
2. 禁用「试试看」「可能有帮助」「一般效果不错」
3. 至少 1 条针对 rank 1 的诊断
4. 允许 `card_id: null` + `novel: true`（库里没有、自己想的），但必须自己写出机制。
   **如果前两条都来自卡片库，第三条尽量自己想一个**；想不出来就诚实说想不出来

> `novel` 字段最后可统计「Agent 提的方案里有多少是自己想的」，是创新分的硬证据。

## ③ 工兵

**输入**：调度器选中的那 1 条提案、配置字段说明、零件接口规范、
**一份现成零件的完整代码当范文**、当前配置、（重试时）上次的完整报错

**输出**

```yaml
change_type: 加新零件          # 只改配置 / 加新零件 / 两者都有
config_patch:
  features.类目兜底: {enabled: true, K: 20}
new_files:
  - path: modules/features/category_fallback.py
    content: |
      <完整文件内容>
self_check:
  - "实现了 FeatureOp 接口的 fit / transform 两个方法"
  - "出现次数只统计训练集，未读取验证集（CLAUDE.md R2）"
  - "K 从配置读取，没有硬编码（CLAUDE.md R7）"
  - "特征列表不含 CLAUDE.md R1 的五个禁用字段"
```

**硬规矩**

1. 只能新建 `modules/` 下的文件或改 `config/`，**绝不许改主程序**（CLAUDE.md R5）
2. 必须输出**完整文件内容**，不许给 diff 片段（生成的行号几乎必错）
3. `self_check` 至少 3 条，其中必须包含对 R1 和 R2 的确认

用小模型跑。重试上限 2 次；第 3 次仍失败则标记 `实现失败`，退回调度器改用 rank 2。

## ④ 复盘官

**输入**：当轮提案（含 expected）、新成绩单、改动前那一版的结果、用到的那张卡

**输出**

```yaml
verdict: 猜对了            # 猜对了 / 猜错了 / 说不清 / 没跑起来
actual: {购买AUC: +0.0041, 点击AUC: -0.0002}
vs_expected: "预期 +0.003，实际 +0.0041，方向和量级都对上"
symptom_resolved:
  symptom: 冷门商品学不动
  before: 0.071            # 低频桶与高频桶的差距
  after: 0.038
  resolved: 部分           # 是 / 部分 / 否
card_update:
  card_id: 类目兜底
  prior_delta: +0.15       # 限制在 ±0.2
next_hint: "长尾差距仍有 0.038，可叠加『频次自适应 embedding 维度』"
promote: true              # 是否建议升到更高保真度验证
```

**硬规矩**

1. `verdict` 四选一，不许模糊
2. **⭐ 分数涨了但 `resolved: 否` → 必须判 `说不清`**
3. 提升小于 0.0005 一律判 `说不清`（CLAUDE.md R11）
4. `prior_delta` 限制在 ±0.2

> 第 2 条是防止 Agent 自我欺骗的关键：**分数涨了不等于假设成立**，可能只是随机波动。
> 一个能说「涨了，但不是因为我猜的那个原因」的复盘官，是整套系统里最值钱的部分。

## Token 预算参考

| 角色 | 模型 | 每轮输入 | 每轮调用 |
|---|---|---|---|
| 医生 | 大 | 2~3k | 1 |
| 军师 | 大 | 3~4k | 1 |
| 工兵 | 小 | 4~6k（含范文） | 1~3（含重试） |
| 复盘官 | 大 | 2~3k | 1 |
| 筛卡片 / 调度器 / 校验 | 不用模型 | 0 | 0 |

一轮约 15k token，跑 40 轮约 60 万 token。**这个数字最后要报出来**（占评分 15%）。
