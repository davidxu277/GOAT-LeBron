卡片上有四个估计类字段，处置原则：**能测的不猜，不能测的用规则算，规则也算不了的才保留人拍。**

### 训练时间倍数 → 已改成记账 ✅

新增 `agent/loop.py` 的 `TimeLedger`：一张卡真跑过之后，实测耗时自动入账
（`run_round` 在训练成功后记录 `RunResult.seconds`），调度器算性价比时
**实测倍数直接覆盖军师报的数**；没跑过的卡才用卡上的猜测值。
倍数分母是全部运行的中位耗时，自我校准，不用指定基准配置。
账本落盘在 `logs/time_ledger.json`，重启不丢。5 个新测试兜住，26 个测试全绿。

理由：耗时是确定性的资源消耗，跑一次 n=1 就可信，不存在统计问题——
这种数字继续让人猜或让模型猜都是浪费。

顺带给 `RoundLog` 加了 `train_seconds` 字段（区别于整轮的 `seconds`），
逐轮累加就是交付物 #4 要求的 GPU 总时长，成员4 不用另起炉灶。

### 代码难度 → 保留人拍，理由如下

它和训练时间不是同一种成本：训练时间是 GPU 的事，代码难度是**工兵的事**——
这张卡的代码 AI 写不写得出来、要重试几次烧多少 token、失败概率多大。
它在调度器里有两个不可替代的用途：预算紧张时"只留改配置/简单"的过滤器，
以及性价比公式的力气分母。四档对照表（改配置 0.5 / 简单 1 / 中等 2 / 难 3）
虽然粗，但只用于同轮三个方案比大小，档位顺序对就够用，不值得精确校准。
将来若要也改记账，现成信号是工兵的重试次数（`run_round` 的重试循环已经知道
这个数，只是没记）——现在不做，优先级让位。

## 五、交接给成员3：「靠不靠谱」改成规则计算

现状：复盘官每轮输出 `prior_delta`（±0.2 限幅），但**没有任何代码把它应用回
卡片的靠谱度** —— 卡上的数从第一轮用到最后一轮，复盘官白打分。
而且让模型主观决定"调多少"有两个已知问题：打分时它看得到旧分数（锚定偏差，
`Card.as_prompt_block` 里带着"历史靠谱度"），以及同样的实验记录两次可能给不同的数。

**建议改法：模型不打分，规则算分。** 复盘官只做它擅长的因果判断
（verdict 四选一），靠谱度由确定性规则从 verdict 推出来：

```
靠谱度 = 卡上的初始先验
       + 0.15  verdict=猜对了 且实测 delta 超过噪声带
       + 0.05  目标病的指标确实改善（symptom_resolved=是/部分）
       − 0.10  verdict=猜错了
       − 0.15  没跑起来 / 工兵三次写不出来
       限幅 [0.05, 0.95]，逐次累加
```

好处：完全可复现、无锚定（不需要给模型看旧分数）、prior_delta 字段可以从
复盘官的输出 schema 里删掉（少一个可以胡编的数字）。

落点：挂在你计划里的 state 写回层（评审说明里的 P3.1）。计算逻辑本身十几行，
可以照 `TimeLedger` 的样子写一个 `PriorLedger`（load/dump/apply 三个方法），
`CardLibrary.get` 读取时用账本值覆盖 yaml 初始值 —— yaml 保持人写的先验不动，
"人拍的 0.55 vs 实测的 0.7" 这种对照本身就是报告素材。

数值本身（+0.15/−0.10）是我拍的，方向和相对大小是有意的：
奖惩不对称（涨得快跌得慢会让失败卡反复还魂，所以跌更狠）；
"没跑起来"罚最重（写不出来的卡继续推荐纯属浪费轮次）。具体数字你可以调。
