## 二、卡住的地方 —— 需要成员1 回应

尝试跑 NISE 基线复现时，检查了新放进 `字节Hackathon/aliccp_train_exposures_16383.xlsx`
这份数据，发现三个问题，**目前判断它不能直接用来复现基线**：

1. **规模太小，统计上不够用**：16383 行里点击 738 条，**转化只有 4 条**。CVR AUC 是在点击
   子集上算的，分母 738、正样本 4 个的量级完全撑不起一个有意义的 AUC——换个切分方式结果
   可能天差地别，甚至可能触发"只有一类样本"的报错。
2. **文件自己标注了这不是给训练用的**：里面第三个 sheet（`conversion_report`）写着
   `source_parquet: /Users/huyaofu/.../NISE/testing/o...`，并明确警告"Excel 仅供人工查看；
   训练应继续读取原 Parquet"。看起来这是某次数据管线开发过程中导出的预览样本，不是最终
   训练数据。
3. **字段 schema 和官方 `torch-rechub` 预处理脚本对不上**：这份文件的标签列叫 `conversion`，
   但 `baselines/mlp_model.py` 期望的列名是 `purchase`；官方脚本只给 8 个多值字段配权重列
   （D109_14 等），这份文件几乎给每个字段都配了权重列，覆盖范围不一致。看起来是成员1
   自己设计的 schema（跟 `数据/aliccp_schema.json` 吻合），跟 NISE 官方预处理管线是两套
   不同的东西。

**需要成员1 确认两件事**：
- 完整规模的 Parquet 文件放在哪 / 什么时候能给到（复现基线至少要接近官方 4200万/4300万
  的量级才有意义）；
- 基线复现是走官方 `torch-rechub` 预处理脚本（最贴近论文原始数字，风险最低），还是走
  你自己那套 schema（后续 Agent 训练管线本来就要用它，两边统一，但需要写一层转换代码，
  且要注意别引入跟官方论文不一致的预处理差异）。

在这个决定下来之前，我不会拿这份小样本硬跑出一个数字充当"官方基线"——量级不够，写进
`CLAUDE.md`/`task_brief` 反而会误导后面所有的阈值和判断。
