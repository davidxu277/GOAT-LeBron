# 实时看板计划 · 成员2

> 2026-08-27 · 目标：一个本地网页，能填数据路径启动运行、实时看四个角色的思考流、翻历史日志。
> 定位说清楚：**比赛交付物不含前端**——这个看板的价值是 (a) 挂机时自查，(b) 答辩演示素材，
> (c) 让"实时思维链"这件事有地方看。它永远排在核心循环之后。

## 一、架构：两进程 + 一个事件文件，彻底解耦

```
Agent 进程                         看板进程                    浏览器
(agent.cli run)                   (web/server.py, Flask)
    │                                  │
    ├─ 每个事件追加一行 ──────►  logs/live_events.jsonl
    │   (agent/events.py)              │ tail 这个文件
    │                                  ├─ SSE 推流 ──────────►  实时思考面板
    └─ 每轮照旧写 rounds.jsonl ──►     └─ 普通 GET ──────────►  历史轮次/账本
```

**为什么这么设计**：Agent 进程只干一件额外的事——往一个 jsonl 文件追加事件（`agent/events.py`，
约 30 行，写完即 flush）。看板服务器 tail 这个文件推给浏览器。两边零耦合：
看板崩了不影响跑分；Agent 不装看板照样跑；室友的循环代码只需要插 2-3 行 emit 调用。

## 二、事件契约（新代码都按这个发）

```json
{"ts": "…", "type": "round_start",  "round": 3, "fidelity": "小份"}
{"ts": "…", "type": "llm_start",    "round": 3, "role": "医生", "model": "…"}
{"ts": "…", "type": "llm_delta",    "round": 3, "role": "医生", "text": "增量文本", "kind": "reasoning|answer"}
{"ts": "…", "type": "llm_end",      "round": 3, "role": "医生", "tokens_in": 2100, "tokens_out": 430, "retries": 0}
{"ts": "…", "type": "phase",        "round": 3, "name": "筛卡片", "detail": "命中 3 张，排除 2 张"}
{"ts": "…", "type": "recovery",     "round": 3, "text": "工兵实现失败(…)，换备胎"}
{"ts": "…", "type": "metrics",      "round": 3, "ctr_auc": 0.61, "cvr_auc": null}
{"ts": "…", "type": "round_end",    "round": 3, "verdict": "说不清", "seconds": 42.0}
```

`kind: reasoning` 单独标出来是给"思维链"留的位子——模型若返回独立的推理内容
（reasoning_content 字段），前端折叠显示为"推理过程"，和正式回答分开；
若模型不提供，这一类事件就不存在，UI 不显示这个区块，**不伪造思维链**。

## 三、页面布局（单页，零构建，vanilla JS）

```
┌─────────────────────────────────────────────────────────┐
│ 顶栏：第 3 轮 · 小份 · 已花 4.2 万 token ($0.03) · 预算▓▓░ │
├──────────┬───────────────────────────────┬──────────────┤
│ 轮次时间线 │  实时思考流                     │ 账本          │
│ ① 类目兜底 │  [医生] ▍逐字流式输出…          │ 卡片信任分     │
│   猜对了✓ │  （推理过程 ▸ 可折叠）           │ 实测耗时       │
│ ② ESMM   │  [军师] …                      │ 已试黑名单     │
│   说不清─ │  [工兵] …                      │              │
│ ③ (进行中)│  [复盘官] …                    │              │
├──────────┴───────────────────────────────┴──────────────┤

```

点左侧某一轮 → 中间面板切到该轮的完整回放（从 rounds.jsonl 读）。

## 四、"输入本地数据"怎么做——不做上传，做路径 + 预检

本地服务器给自己上传文件是仪式感。改成一个启动表单：

- 三个路径输入框：`train.csv` / `val_features.csv` /（可选）评分脚本路径
- 轮数 N、token 预算两个数字
- **预检按钮**：服务器读文件头部，当场显示行数 / 点击数 / 转化数，并按之前定的
  标准亮红绿灯（验证集 <20 万行 → 黄警告；转化 <50 条 → 红警告"购买 AUC 将不可信"）
  ——把"数据够不够大"的检查从口头约定变成页面上的硬提示
- 启动 → 服务器 `subprocess` 拉起 `agent.cli run --rounds N …`；停止按钮发信号杀进程

## 六、技术选型与边界

- **Flask + SSE + 原生 JS**，单文件服务器 ~150 行，零 npm 零构建——今晚没时间伺候 React
- 服务器只绑 `127.0.0.1`，不对外
- 事件文件里**永远不出现 API key**（events.py 只接受白名单字段）
- 新目录 `web/`，不碰室友的车道；唯一交界是 loop.py 里 2-3 行 emit（round_start/end），
  给他递个三行 patch 就行
- `logs/` 本来就不入库（README 写明），live_events.jsonl 跟着沾光
