## 一点五、读完 baseline 源码后新增的两个未决问题（优先级最高）

详见 `docs/baseline笔记.md` 第零节。这两条不确认，后面实验都可能白做。

### Q1 · 购买 AUC 的计算范围

官方 baseline NISE 是在**全部曝光**上算购买 AUC 的
（`mtl_trainer.py:424`，`targets[:, 0]` 没有筛 `click == 1`）。
我们的红线文件原本写的是「仅 click=1」，还把全曝光口径列成了危险信号。

已改：CLAUDE.md 第五节改成「待确认」，要求代码两种口径都算都记，
报分暂用「仅点击」。**需要拿到主办方的评测脚本才能定。**

### Q2 · 官方 baseline 到底是 NISE 还是它的对照组

NISE 论文的核心主张是它打赢了 ESMM / MMoE / IPS / DR / DCMT。
如果官方 baseline 就是 NISE，那照搬这五个方法 **delta 是负的**。

这直接影响 7 张新卡的价值 —— 所以它们的 `预计能提多少` 全填 0、
`靠不靠谱` 全填 0.5，并在 `前提条件` 里写死了这道闸门。
**想听意见**：卡上的「预计能提多少」只是给军师看的提示
（`Card.as_prompt_block`），调度器算性价比用的是**军师自己报的** `expected`。
所以填 0 不会硬性封死这些卡，只是把军师的预期往低处锚。
这个软约束够不够？还是应该在卡上加一个硬字段，让调度器直接跳过
方向未确认的卡？

## 二、我们已经知道的三个弱点

这几条不用再指出来，直接看第三节更有用。

### 1. `symptoms.yaml` 里的阈值全是拍的

0.03、0.04、0.002、0.0005 这些数字**没有任何依据**，不是测出来的也不是从论文抄的。

已经知道的问题：固定阈值在不同数据量下错得很离谱。用 Hanley-McNeil 公式
在自己的假数据上算过：

| 分组 | 正样本数 | AUC 噪声（2×标准误） |
|---|---|---|
| 小份数据，>1000 桶 | 47 | **0.086** |
| 全量数据，<10 桶 | 41,200 | **0.003** |

同一个 0.03，小数据上会把纯噪声当病报，大数据上会漏掉真实差距。

**进展（08-27）**：工具已经落地 —— `agent/noise.py`。同配置换 N 个种子跑，
量出每个分桶的实测抖动，再用 Hanley-McNeil 从正样本数算一个理论值交叉验证。

    python -m agent.cli noise --seeds 3 --train ... --val-features ...

测出来的带子写进 `logs/noise_bands.json`，之后自动生效于两处：
挂到成绩单上给医生看（哪些差距是真的），以及顶掉复盘官那个 0.0005 的门槛。
**`symptoms.yaml` 里的数字一个都没动** —— 那份要改得成员2 和成员3 一起改。
剩下的一步：在真数据上跑一次，把结果贴回来。

### 2. 判病是 LLM 在做，不是代码在做

现在的实现是把 `detect` 规则当文本塞进提示词，让模型自己读数字、做减法、比大小。

后果：不可复现（同样数据两次可能报不同的病）、算术可能出错。

**计划**：改成"代码先按规则精确算，医生负责复核可信度 + 排优先级 + 发现规则外的异常"。
判病这件事本来就该是确定性的 —— 创新分看的是军师的推理，不是医生的减法。

### 3. 单元测试覆盖的是"代码强制"那一层，不是提示词质量

57 个测试全在测校验器与接线（证据有没有数字、禁用字段有没有拦住、
复盘官会不会自欺、状态有没有传下去、崩了能不能恢复）。
提示词好不好只能靠人拿真模型跑 5 份假成绩单去看。

### 4. 复盘官的"目标指标"还是它自己报的

`symptom_resolved.before/after` 由模型填。现在代码会检查这两个数**互相**自洽
（说治好了就不许两个数一模一样），但没法验证这两个数是不是真的从成绩单里抄来的。
彻底解决要走"判病改成代码算"那条路（弱点 2），届时 before/after 由代码填。

## 三、还没想清楚的（这里最需要意见）

### A. 新病发现机制

12 个病是人写的，一定会漏。目前的方案草稿：

- 医生每轮多输出一个 `observations` 字段（自由文本，不受词表约束），
  专门装"规则没覆盖但数字看着不对劲"的东西
- 连续 3 轮复现 + 能写成可计算规则 + 至少能想出一种治法 → 升级成新病，
  写进 `symptoms_discovered.yaml`（**不动** `symptoms.yaml`，成员2 的契约不受影响）
- 新病通过 `treatable_by` 反向指针链接到现有卡片；指针为空时把全部 20 张卡
  摘要给军师看一遍（约 3000 token，只在有新病的那轮发生）

**想听意见的点**：
1. "连续 3 轮"这个门槛合理吗？会不会太严（跑 40 轮的话，第 35 轮发现的新病永远升级不了）
2. 有没有比"自由文本 observations"更好的表达方式
3. 这个机制会不会让医生倾向于每轮都硬编一个"新发现"来显得自己有用

### B. 卡片与病的对应关系能不能被实验修正

设想：复盘官发现某张卡治好了它标签上没写的病，就记一条 `learned_links`，
下次遇到那个病这张卡也会被筛出来。

**想听意见的点**：这算不算过度设计？在只有 40 轮的规模下，
一条 learned_link 大概率只被用上一两次，值不值得做。

### C. 医生和军师的边界

现在医生只报病、不开药，军师只开药、不看原始数据。
这样切是为了让两边的上下文都小、职责单一。

**想听意见的点**：军师看不到原始成绩单，只看医生转述的诊断 ——
会不会丢掉重要信息？还是说这种信息瓶颈反而是好事（逼医生把话说清楚）？
