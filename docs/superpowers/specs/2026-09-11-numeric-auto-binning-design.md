# 数值特征自动分档 —— 设计

日期：2026-09-11 · 状态：用户已批准方案 A

## 问题

`harness/deep.py` 的 `Vocab` 把每一列的**每个不同取值**登记成一个类别 ID，
验证集里训练时没见过的值一律落进 OOV（0 号槽）。

对 ID 列这是对的；对 Agent 写的统计类特征（目标编码、看完率、混合热度）是错的：
这些列是小数，训练集和验证集算出来的数几乎对不上。实测（造数据，500 个视频，
目标编码走 `apply_feature_ops`）：**验证集 37% 的行落进 OOV**，剩下的也只是
数值恰好撞上 —— 模型学到的不是"看完率高低"。

现状是在卡片上提醒工兵"要先分档"，也就是靠自觉。

## 方案（A：在 Vocab 这一个入口统一分档）

所有深度训练路径（KuaiRand 的 goat_trainer、AliCCP 的 RealExecutor）
都只在 `train_deep` 里建一次 `Vocab`，验证、测试预测复用同一个对象 ——
在这里分档，一处改动覆盖全部路径，训练/验证/测试天然一致。

- **哪些列分档**：浮点类型，且训练集里不同取值的个数 > `numeric_bins`。
  整数列（出现次数、已经分好的档）、取值很少的小数列、category 类型照旧按取值编号。
- **怎么分**：用训练集的分位数切 `numeric_bins` 档，重复的边界去重。
  编码 = `searchsorted(边界, 值, side="right") + 1`。超出训练范围的值落到两端的档；
  NaN 落 OOV。
- **边界只用训练集算**（R2），存在 `Vocab` 里，验证/测试沿用。
- **档数从配置读**（R7）：`model.deep.numeric_bins`，加进 `DEEP_PARAMS`
  白名单，区间 2~256，默认 32。
- **看得见**：`train_deep` 的训练记录新增 `自动分档的列`。
  runner 已经把整份训练记录放进成绩单「训练诊断 → 每轮训练记录」，不用另改。
- **`Vocab()` 不传档数时行为不变**（不分档），只有 `train_deep` 传。

## 不做的事

- 不改 FeatureOp 接口，不要求零件声明"我是连续值"—— 从 dtype 推，不靠声明。
- 不做可学习的分档 / 连续值直接进网络 —— ModelOp 接口只收整数张量，那是另一件事。

## 验收

1. 复现上面的实验：目标编码列经 `Vocab(numeric_bins=32)` 后，验证集 OOV 比例 < 1%。
2. 整数列、取值少的小数列编码与改动前完全一致。
3. 超出训练范围的值不落 OOV；NaN 落 OOV。
4. `train_deep` 的训练记录里有 `自动分档的列`，且列出的正是被分档的列。
5. 全量测试不退步。
6. 卡片上"要先分档"的提醒删掉（目标编码、用户历史序列、DIN 的退路一句），
   改成"流水线会自动分档"。
