# 每轮看得见：角色级过程记录

## 要解决什么

跑起来时人看不见任何东西。

- 真跑那条路（`kuairand_bridge.goat_run`）没有传 `on_round`，整场跑下来终端一行不打。
- 离线演习每轮只打一行：轮次 / 档位 / 卡片 / 结论 / 分数。
- 四个角色的输出确实进了 `logs/rounds.jsonl`，但那是一行几万字的 JSON，人读不了。
- 网页看板（成员2 的）能看到「大模型在想」和恢复事件，没有按角色整理成一轮的经过。

还有四样东西**根本没记下来**，跑完就没了：

1. 筛卡给军师摆了哪几张候选卡、当时的信任分是多少
2. 调度器选了谁、用多大数据、备胎是谁
3. 工兵的每一次尝试 —— 现在只留最后能跑的那一版，前几次写错的代码和试跑报错只剩一行摘要
4. 每个角色花了多少时间、多少 token

第 3 条是刚上线的试跑功能最需要的证据：「工兵第一次写错、拿到报错后第二次改对」
这件事现在只在终端一闪而过，日志里看不出来。B5（过程指标）要算执行成功率，也要它。

## 做成什么样

### 终端：每做完一步就打

```
第 3 轮 · 中份数据
  医生    发现 2 个病：时间漂移（严重 0.7，把握高）、新用户冷启动（0.4）
          证据：按曝光次数分组，最低桶 GAUC 0.612，最高桶 0.681
  筛卡    对症的卡 5 张：时间衰减加权(0.60) 行为序列(0.50) 类目兜底(0.50) …
  军师    提了 3 个方案，第一个「时间衰减加权」，预计 GAUC +0.001
  调度    选「时间衰减加权」，中份数据，备胎：行为序列、类目兜底
  工兵    第 1 次：新写 modules/features/time_decay.py，配置改 2 行
  试跑    挂了 —— KeyError: 'play_time'
  工兵    第 2 次：重写同一个文件
  试跑    过了（4.8 秒）
  训练    GAUC 0.6692 · nDCG@5 0.5433 · 主分 0.6062（218 秒）
  复盘官  猜对了：GAUC +0.0008、nDCG@5 +0.0031，超过噪声带
          下一步：去看新用户那一组
  本轮    3 分 41 秒 · 3.8 万 token
```

要求：**一步做完就打一次**，不是等整轮结束一起打。一轮真跑要几分钟到几十分钟，
攒到最后打等于没有。

### 每轮一份 markdown 全文

落在 `<logs_dir>/rounds/<哪一场>/round_003.md`（跟 `snapshots/` 同一个命名法）。
内容是终端那几行的完整版：

- 医生：全部发现，每条的证据原文
- 筛卡：候选卡清单（编号、名字、治哪些病、信任分）
- 军师：全部方案，每个的理由、预计、代价、风险
- 调度：选中的方案全文、档位、备胎
- 工兵 × 每一次尝试：第几次、改了什么、**失败那几版的完整代码**、试跑的完整报错
  （成功那一版的代码不重抄，`rounds.jsonl` 的 `patch_files` 里有）
- 训练：成绩单原文
- 复盘官：全文（结论、实际变化、病有没有好转、下一步）
- 本轮小结：耗时、token、恢复事件

## 怎么实现

### 新文件 `agent/trace.py`

只管排版，不碰主流程。三个东西：

- `步骤摘要(步骤: str, 内容) -> list[str]` —— 把一步的输出压成 1~2 行人话。纯函数。
- `class Tracer` —— `step(步骤, 内容)` 调上面那个再打到终端。
  `printer` 可注入（测试传 list.append），`enabled=False` 就什么都不干。
  **整个 `step` 包在 try 里**：排版出 bug 绝不能把正在跑的一轮弄崩，
  跟 `agent/events.py` 一个待遇。
- `render_round(log) -> str` / `write_round_md(logs_dir, log) -> Path` —— 从 `RoundLog`
  拼 markdown。纯函数 + 一个写文件。

终端和 markdown 共用同一批摘要函数，不许两份排版逻辑。

### `RoundLog` 补四个字段

| 字段 | 内容 |
|---|---|
| `candidates` | `[{"card_id", "名字", "治哪些病", "信任分"}]` —— 筛卡摆给军师的那几张 |
| `backups` | 备胎的 card_id 列表 |
| `attempts` | 工兵每一次：`{"候选", "第几次", "新文件", "config_patch", "试跑", "报错", "失败代码"}` |
| `steps` | `[{"角色", "秒", "token"}]` —— 每步的时间和 token |

`失败代码` 只在这一次失败时才填，成功那版指向 `patch_files`，同一份代码不存两遍。

`attempts` 里的 `试跑` 三种值：`过了` / `挂了` / `没试跑`（执行器没有 `smoke`，
或者试跑本身坏了被 `_guard` 放行）。

### `agent/loop.py` 接线

- `run_round` 多一个可选参数 `tracer: Tracer | None = None`。每一步做完：写进 `log`
  的新字段，再 `tracer.step(...)`。`tracer=None` 时只记不打 —— 现有测试行为不变。
- token 用 `llm.ledger.total_tokens` 的差值算，时间用 `time.time()` 差值。
- `run_session` 多一个 `trace: bool = True`。为真就自己造一个 `Tracer` 传下去，
  并把 `write_round_md` 挂进那个已有的「落盘」循环（快照 / 逐轮日志 / 账本 / 待议架
  那一组）—— 那段本来就包了保险丝，写失败只记一笔恢复事件。
- 离线演习原来那个 `on_round` 一行摘要保留：它是**跨轮**的一览，不跟角色级的重复。

### 真跑那条路

`goat_run` 调 `run_session` 时什么都不用改 —— `trace` 默认为真就有了。

## 出错怎么办

| 出错的地方 | 后果 |
|---|---|
| 摘要函数抛异常 | `Tracer.step` 吞掉，这一行不打，训练照跑 |
| markdown 写不进去（磁盘满等） | 落盘循环记一笔「角色日志写失败」，整场继续 |
| 某个角色炸了（本来就有的情况） | `_guard` 记恢复事件，`log` 的字段停在那一步，markdown 照样能渲染（缺的段落写「没走到这一步」） |

原则跟看板一样：记录是旁观者，绝不反过来弄崩跑分。

## 怎么测

- `步骤摘要` 每个步骤一个测试：给一份真实形状的输出，断言关键数字出现在结果里
  （病名、卡片编号、分数、报错首行）。
- `render_round`：手搓一个走完全程的 `RoundLog`，断言八个段落都在，
  失败那一版代码在、成功那一版不重抄。
- 半路死掉的 `RoundLog`（只有医生）也能渲染，不抛异常。
- `Tracer`：`printer` 注入 list，断言顺序；摘要函数故意抛异常时 `step` 不往外抛。
- 接线：离线跑一轮，断言 `candidates` / `backups` / `attempts` / `steps` 都有内容，
  工兵失败重试的那一轮 `attempts` 有两条、第一条带报错。
- `run_session` 跑完，断言 `logs/rounds/<场次>/round_001.md` 存在且非空。
- 真数据一轮（不调大模型，用写好剧本的假模型）：把终端输出和 md 文件发给用户看。

## 不做

- 不动网页看板的事件流契约（`agent/events.py` 的白名单、`web/console.html`）。
  那是成员2 的地盘，两边同时改容易打架。
- 不记每个角色收到的完整提示词。一轮几万字，而且提示词本身在仓库里。
