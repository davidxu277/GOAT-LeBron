# 训练前先试跑 —— 设计

日期：2026-09-12 · 状态：用户授权自行决定（"你来决定怎么跑"）

## 问题

2026-09-01 真跑 7 轮里 4 轮一跑就挂。现在一次代码错误的代价：

- 占掉一个官方训练名额（上限 50）
- 整轮作废：四个角色的 token 已经花了，却什么都没学到
- 卡片被记「没跑起来」扣信任分 —— 可写错代码的是工兵，不是方法本身
- **报错从来没交回工兵**：只有「没过校验」会把错误文本给它重试，训练崩了不会

真数据实测（2026-09-12，不调大模型，直接用执行器）：

| 情况 | 结果 | 耗时 | 训练名额 |
|---|---|---|---|
| 第 0 轮，小份 | 主分 0.5800 | 11s | 用掉 1 个 |
| 挂现成零件（视频热度分桶） | 主分 0.5798，「改动是否生效：生效」 | 12s | 用掉 1 个 |
| 故意写错的零件 | 3 秒就挂，报错带完整 traceback（44 行） | 3s | **照样用掉 1 个** |

traceback 其实已经在 `RunResult.error` 里（`ChildRunnerError` 把子进程的 traceback
拼进了消息），只是没人把它交回工兵。

## 方案

### 执行器：`KuaiRandGoatExecutor.smoke(patch) -> BridgeRunResult`

- 用「当前补丁历史 + 这次的补丁」原样重放，但只取训练集 **2%**（新保真度档 `试跑`）、
  训练轮数改成 **1**（覆盖 `model.deep.epochs`）
- **不占训练名额**（不调 `_reserve_training_attempt`），**不写进补丁历史**
- 输出目录 `output_dir/smoke/NNN`，跟正式轮次分开
- 返回 `ok` / `error`（含完整 traceback）/ `seconds` / `unsupported`

### 外层循环：`run_round` 在正式训练之前试跑

- 执行器有 `smoke` 才试跑（`FakeExecutor` / `DriftingExecutor` 没有，行为不变）
- 工兵交出补丁 → 试跑：
  - 过了 → 照常正式训练
  - 挂了 → traceback **最后 40 行**（上限 4000 字）作为 `last_error` 交回工兵，
    同一个方案最多再改 **2 次**（`SMOKE_RETRIES`）
  - 还挂 → 换备胎方案，每个备胎同样有 2 次机会
  - 执行器说兑现不了（`unsupported`）→ 不让工兵重试（它改不了），直接换备胎
  - 所有方案都挂 → 本轮结束：**不占训练名额、不扣卡片信任分**，记进恢复记录；
    这一轮仍算「跑不起来」，连续失败判停照常生效
- 每次试跑写一条恢复记录：哪个方案、第几次、报错首行

### 为什么不直接拿正式训练的报错去重试

正式训练失败要占训练名额，而且小份之外的档位（中份 40%、全量）一次要更久。
试跑把"写错代码"这类失败挡在花名额之前。

## 不做的事

- 不把试跑结果当成绩：它只回答"跑不跑得通"
- 不改离线演习的假执行器（需要时测试里自己造一个带 `smoke` 的假执行器）

## 验收

1. 带 `smoke` 的假执行器：试跑先挂两次、第三次过 → 工兵被叫了 3 次、第 2、3 次的输入里
   带着上一次的 traceback；正式训练只跑 1 次
2. 试跑一直挂 → 正式训练一次都没跑、卡片信任分没被扣、恢复记录里有试跑失败
3. 没有 `smoke` 的执行器 → 行为跟以前一模一样（现有测试全绿）
4. 真执行器：`smoke` 不占训练名额、不改补丁历史；写错的零件在真数据上几秒内挂掉并带 traceback，
   写对的补丁试跑能过
