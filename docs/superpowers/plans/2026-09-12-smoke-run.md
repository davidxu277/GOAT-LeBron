# 训练前先试跑 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 工兵的代码先在极小一份数据上试跑；挂了就把 traceback 交回工兵有限次重试，不占训练名额、不扣卡片信任分。

**Architecture:** 执行器加一个可选的 `smoke(patch)`（2% 训练集、1 轮、不进补丁历史、不占名额）；
`run_round` 在正式训练前调用它，失败时把 traceback 尾部作为 `last_error` 交回工兵。
没有 `smoke` 的执行器（假执行器）行为不变。

**Tech Stack:** Python 3.14、pytest、multiprocessing（执行器子进程）

Spec: `docs/superpowers/specs/2026-09-12-smoke-run-design.md`

## Global Constraints

- 试跑档位名 `试跑`，训练集比例 0.02；goat_trainer 下训练轮数强制 1（补丁历史末尾追加 `model.deep.epochs: 1`）
- 同一个方案试跑失败后最多再让工兵改 2 次（`SMOKE_RETRIES = 2`）
- 交回工兵的报错：最后 40 行、上限 4000 字
- 试跑不调 `_reserve_training_attempt`、不改 `_patch_history`
- 提交信息不加 Co-Authored-By；每个 Task 结束全量测试 0 失败

### Task 2: `run_round` 在正式训练前试跑

**Files:**
- Modify: `agent/loop.py`（`SMOKE_RETRIES`、`_smoke_feedback`、`run_round` 的工兵循环）
- Test: `tests/test_smoke_run.py`

**Interfaces:**
- Consumes: 执行器上可选的 `smoke(patch) -> RunResult`
- Produces: `loop.SMOKE_RETRIES: int`、`loop._smoke_feedback(error: str) -> str`

- [ ] **Step 1: 写失败测试**（假执行器继承 `DriftingExecutor`，加 `smoke`，可设前 N 次失败 / `unsupported`；
  假模型继承 `ScriptedLLM`，记下每次工兵的输入）：
  1. 试跑挂两次、第三次过 → 工兵被叫 3 次；第 2、3 次输入里带着上一次的报错；正式训练只跑 1 次
  2. 试跑一直挂 → 正式训练 0 次；信任分账本没被动；恢复记录里有「试跑」
  3. 试跑说兑现不了（unsupported）→ 每个方案只实现 1 次就换备胎；正式训练 0 次
  4. 没有 `smoke` 的执行器 → 工兵 1 次、正式训练 1 次（行为不变）
  5. `_smoke_feedback` 只留最后 40 行、不超过 4000 字
- [ ] **Step 2: 跑，确认失败**
- [ ] **Step 3: 实现** —— 工兵循环里每个方案最多 `1 + SMOKE_RETRIES` 次；试跑本身抛异常用 `_guard` 兜住并放行
  （不因为试跑坏了而卡住整轮）；所有方案都没过时恢复记录注明「试跑拦下，没占训练名额」
- [ ] **Step 4: 跑新测试 + 全量 + 离线演习**
- [ ] **Step 5: 提交并推送**
