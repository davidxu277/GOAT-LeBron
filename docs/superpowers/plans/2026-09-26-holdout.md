# 锁定集 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 验证集按用户切出 20% 当锁定集。一场里所有决策只看另外 80%（开发集）；
整场结束后，拿第 0 轮和最佳轮各训一次，分别在开发集和锁定集上打分，
报「开发集涨了多少 / 锁定集涨了多少」—— 差出来的那部分就是反复看开发集挑出来的运气。

**为什么：** Agent 跑 N 轮都在看同一份验证集挑最好的一轮，「最好」里混着恰好迎合它的部分
（多重比较）。B1 实测单种子抖动就有 ±0.003~0.005，跑 20 轮挑最高的那个，光运气就能挑出好几个千分点。

**Architecture:**
- `DatasetBundle.with_valid_part(part, holdout_frac)`：`全部` / `开发` / `锁定`，按 `crc32(user_id)` 分桶，确定性。
- `run_trainer(valid_part=..., holdout_frac=...)`：
  - `全部`（默认）一切照旧
  - `开发`：一开始就把 valid 换成开发集 —— 评分、医生的分组证据、预测全跟着换
  - `裁决`：训一次，在全量 valid 上预测一次，开发集和锁定集**分别**打分（`validation` = 开发集，`holdout` = 锁定集）
- 执行器 `holdout_frac`（默认 0 = 关）：开着时 `run` / `smoke` 走 `开发`；
  新方法 `holdout_verdict(rounds, fidelity)` 对每个执行器轮次重放补丁历史、走 `裁决`；
  `make_final_submission` 永远 `全部`（跟官方基线比的就是它）
- `goat_run`：任务配置 `holdout_users: 0.2`；开着时预留 2 个训练名额给大考；
  跑完对 [第 0 轮, 最佳轮] 做大考，结果写进 `session_summary` 和 `holdout_report.json`

## Global Constraints

- `holdout_frac=0` / `valid_part="全部"` 时行为与现在逐字节一致
- 执行器只在开了锁定集时才把 `valid_part` / `holdout_frac` 传给 runner（假 runner 不认）
- 锁定集的分数绝不进任何一轮的成绩单（医生、军师、复盘官、外层循环都看不到）
- 大考在整场结束后才做，结果不回流任何决策
- `require_baseline_reproduction` 与锁定集同时开 → `validate_task` 直接报错并说明原因
- 提交不加 Co-Authored-By；每个 Task 结束全量测试 0 失败
